# Практика 7: Рекомендательная система для медиакаталога

Проект реализует полный пайплайн построения и сравнения рекомендательных систем на реальных данных:
загрузка и очистка, разведочный анализ, обучение нескольких моделей, единая оценка по всему каталогу
и анализ того, чем модели отличаются не только по точности, но и по покрытию каталога и разнообразию выдачи.

Реализованы три семейства подходов и бейзлайн:

| Модель | Подход | Библиотека | Данные |
|---|---|---|---|
| `popular` | бейзлайн «Популярное» | numpy | любые |
| `content` | контентный: TF-IDF + косинусное сходство | scikit-learn | любые |
| `svd` | коллаборативный на явных оценках | scikit-surprise | только явные оценки |
| `als` | коллаборативный на неявных данных | implicit | любые |
| `bpr` | неявные данные, парная функция потерь | implicit | любые |

Дополнительно: переранжирование **MMR** (Maximal Marginal Relevance) для повышения разнообразия выдачи.

Обязательный элемент работы: сравнение всех моделей с бейзлайном «Популярное», оценка метрик ранжирования,
покрытия каталога, разнообразия и новизны выдачи, проверка статистической значимости различий.

### Как устроен код

- `data.py` приводит любой датасет к единому виду: таблица взаимодействий `user, item, rating, timestamp`
  и таблица метаданных объектов `title, text, genres`. Класс `Dataset` хранит «сырой» набор, класс `Split` -
  результат фильтрации и сплита (идентификаторы пользователей и объектов переиндексированы в 0..N-1).
- `models.py`: все модели имеют общий интерфейс `fit(split)` и `score(users) -> матрица (пользователи × объекты)`.
  Благодаря этому оценка и MMR не зависят от конкретной модели.
- `evaluate.py` выбирает top-K по всему каталогу, исключая объекты из train, и считает метрики по пользователям
  отдельно для сегментов `all`, `light`, `heavy`.
- `recsys.py` связывает все части и пишет артефакты.

## 2. Установка

Требуется Python 3.10+ (проверено на 3.12).

Создайте виртуальное окружение и установите зависимости.

**Linux / macOS:**
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

**Windows (PowerShell):**
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Зависимости (`requirements.txt`): numpy, pandas, scipy, scikit-learn, matplotlib, scikit-surprise 1.1.5,
implicit 0.7.3, pytest.

Если `scikit-surprise` не ставится из-за конфликта с версией numpy, установите его в отдельном окружении
или соберите из исходников:
```bash
pip install scikit-surprise --no-binary scikit-surprise
```
Без `surprise` и `implicit` работают модели `popular` и `content`; для `svd` и `als/bpr` при их запуске
будет выдано понятное сообщение об отсутствующей библиотеке.

## 4. Запуск

Все вычисления выполняются через CLI-скрипт `recsys.py`.

### Примеры

MovieLens (все модели, EDA, MMR):
```bash
python recsys.py --dataset movielens --path data/ml-latest-small --model all --k 5 10 --eda --evaluate --mmr 0.5 0.7 0.9 --output results/ml
```

Last.fm (неявные данные, без SVD):
```bash
python recsys.py --dataset lastfm --path data/hetrec2011-lastfm-2k --model popular,content,als --k 10 --evaluate --output results/lastfm
```

Только выгрузка рекомендаций (без расчёта метрик):
```bash
python recsys.py --dataset movielens --path data/ml-latest-small --model popular,als --output results/recs_only
```

Быстрая проверка без датасетов (синтетические данные):
```bash
python tests/smoke_synthetic.py
```

### Рекомендация перед запуском ALS/BPR

Библиотека `implicit` предупреждает о многопоточности BLAS. Чтобы убрать предупреждение и ускорить обучение,
задайте перед запуском:

```bash
export OPENBLAS_NUM_THREADS=1          # Linux / macOS
$env:OPENBLAS_NUM_THREADS=1            # Windows PowerShell
set OPENBLAS_NUM_THREADS=1             # Windows cmd
```

### Что выводится в консоль

Размеры данных после фильтрации, время обучения каждой модели, таблица вердиктов значимости
относительно бейзлайна (по MAP) и сводная таблица метрик для максимального K.

| Аргумент | Описание | По умолчанию |
|---|---|---|
| `--dataset` | `movielens`, `lastfm` или `amazon` (универсальный CSV-формат, см. раздел 12) | обязателен |
| `--path` | путь к папке с датасетом | обязателен |
| `--model` | `popular`, `content`, `svd`, `als`, `bpr`, список через запятую или `all` | `all` |
| `--k` | значения K для метрик, например `--k 5 10` | `10` |
| `--evaluate` | рассчитать метрики (без флага скрипт только выгружает рекомендации в `recs.json`) | выкл. |
| `--eda` | построить графики и статистику разведочного анализа | выкл. |
| `--mmr` | значения λ для MMR-переранжирования контентной модели, например `--mmr 0.5 0.7 0.9` | пусто |

| `--seed` | seed генератора случайных чисел | `42` |
| `--output` | папка для результатов | `results` |

Замечания:
- `--model all` на датасете без явных оценок (Last.fm) автоматически пропускает SVD.
- MMR применяется только к модели `content`; она должна присутствовать в `--model`.
- Рекомендации строятся до глубины `max(K, 10)`.

## 6. Протокол оценки

1. **Фильтрация (k-core):** итеративно удаляются пользователи и объекты с менее чем 5 взаимодействиями.
   Предварительно дубликаты пар «пользователь-объект» схлопываются: при наличии времени остаётся последнее
   взаимодействие, иначе - с максимальным весом.
2. **Сплит (поюзерный):**
   - MovieLens - **хронологический**: последние 5 взаимодействий пользователя уходят в тест.
   - Last.fm - **случайный leave-N-out** (5 взаимодействий, фиксированный seed), так как в данных нет времени прослушиваний.
   - Пользователи с историей менее 10 взаимодействий остаются целиком в train и в оценку не входят.
3. **Релевантность:** MovieLens - рейтинг ≥ 4; Last.fm - любое прослушивание. В оценку попадают пользователи,
   у которых в тесте есть хотя бы один релевантный объект.
4. **Ранжирование:** по всему каталогу за вычетом объектов из train пользователя (без сэмплирования негативов).
5. **Метрики:** Precision@K, Recall@K, MAP@K, NDCG@K, покрытие каталога, разнообразие выдачи (intra-list diversity
   в пространстве TF-IDF), новизна, число жанров в списке.
6. **Сегментация:** метрики считаются в целом (`all`) и отдельно для «лёгких» (`light`) и «тяжёлых» (`heavy`)
   пользователей. Граница - медиана числа train-взаимодействий среди оцениваемых пользователей.
7. **Значимость:** для метрик по пользователям рассчитан 95% доверительный интервал (`ci95`).
   Если интервал модели пересекается с интервалом бейзлайна, различие считается статистически незначимым
   (консервативный критерий). Таблица вердиктов по MAP сохраняется в `significance.csv`.

## 7. Модели

### Popular (бейзлайн)
Всем пользователям рекомендуются объекты с наибольшим числом релевантных взаимодействий в train.
Персонализации нет, поэтому покрытие каталога у модели минимально.

### Content-based
TF-IDF (с сублинейным tf) по тексту объекта. Профиль пользователя - среднее векторов объектов, которые ему
понравились (релевантных в train). Оценка объекта - косинусное сходство с профилем. Модель не использует
поведение других пользователей.

### SVD (scikit-surprise)
Матричная факторизация с оптимизацией предсказания оценки (50 факторов, 20 эпох). Обучается на всех оценках
MovieLens. Оценка объекта = глобальное среднее + смещение пользователя + смещение объекта + произведение факторов.
Объекты, отсутствующие в train, получают очень низкую оценку. Работает только на явных данных.

### ALS (implicit)
Факторизация неявных данных (50 факторов, 15 итераций). Обучается на положительных взаимодействиях
(MovieLens - оценка ≥ 4, вес 1). На Last.fm вес взаимодействия - `1 + ln(1 + число прослушиваний)`.

### BPR (implicit)
Байесовская персонализированная ранжирующая модель: оптимизирует порядок пар «объект с взаимодействием выше
объекта без него» (50 факторов, 100 итераций). Обучается на положительных взаимодействиях.

### MMR
Переранжирование top-50 кандидатов контентной модели. На каждом шаге выбирается объект с максимальным значением
`λ · релевантность - (1 - λ) · максимальное сходство с уже выбранными`. Релевантность нормируется на [0, 1] внутри
пула кандидатов. Чем меньше λ, тем сильнее акцент на разнообразии. В таблицах модель называется `content+mmr<λ>`.

## 8. Метрики

| Метрика | Колонка `metric` | Описание |
|---|---|---|
| Precision@K | `precision` | доля релевантных среди первых K рекомендаций |
| Recall@K | `recall` | доля найденных релевантных объектов теста |
| MAP@K | `map` | средняя точность по позициям попаданий; нормировка на min(K, число релевантных) |
| NDCG@K | `ndcg` | дисконтированный кумулятивный выигрыш с бинарной релевантностью |
| Покрытие | `coverage` | доля объектов каталога, попавших хотя бы в один список (на множество пользователей сегмента) |
| Разнообразие | `diversity` | ILD: 1 - среднее попарное косинусное сходство объектов списка в пространстве TF-IDF |
| Новизна | `novelty` | средняя self-information `-log2 p(объект)`, p - доля пользователей, знакомых с объектом в train |
| Число жанров | `n_genres` | число различных жанров (тегов) в списке |

Для всех метрик, кроме покрытия, считается среднее по пользователям и 95% доверительный интервал
`1,96 · σ / √n`. У покрытия интервала нет (метрика множественная).

### Ключевые выводы

**MovieLens (явные данные)**
- Значимо лучше бейзлайна только ALS (MAP@10 0,0417 против 0,0236). BPR статистически от бейзлайна не отличается
  (интервалы пересекаются), но даёт самое широкое покрытие каталога (24,5% против 2,9% у popular).
- SVD значимо хуже бейзлайна (0,0076): он оптимизирует предсказание оценки, а не ранжирование (вероятная причина).
- Контентная модель самая слабая: у фильмов только жанры, теги и название - признаки слишком грубые.

**Last.fm (неявные данные)**
- ALS значимо превосходит и бейзлайн, и контентную модель (MAP@10 0,1374 против 0,0401 и 0,0538).
- Контентная модель здесь значимо лучше бейзлайна: у артистов богатые пользовательские теги.
- Покрытие popular - 1,0%: в выдачах всех пользователей вместе встречается около 29 разных артистов.

**MMR (контентная модель, MovieLens)**
- Разнообразие растёт при уменьшении λ (ILD с 0,672 до 0,698 при λ=0,5), покрытие - с 18,0% до 19,5%.
- MAP@10 практически не меняется (0,0042 → 0,0044); значимость этого изменения отдельно не проверялась.

> Значения сравнивать между датасетами нельзя: у них разные определения релевантности и разный тип сплита.
> Сопоставимы только соотношения моделей внутри каждого набора.

## 11. Тесты

```bash
python -m pytest tests -q
```

`tests/test_metrics.py` содержит 8 юнит-тестов на значениях, посчитанных вручную: Precision/Recall, MAP, NDCG, покрытие,
разнообразие, новизна и число жанров, доверительный интервал, поведение MMR (чистая релевантность при λ=1 и штраф
за схожесть при малых λ).

`tests/smoke_synthetic.py` строит синтетический набор в формате MovieLens и прогоняет весь пайплайн для моделей
`popular` и `content` с EDA, оценкой и MMR. Скрипт не требует `surprise`/`implicit` и не требует скачивания данных;
он проверяет, что все артефакты создаются.

## 12. Использование других датасетов

### Другие версии MovieLens
Любая версия в формате CSV (`ratings.csv`, `movies.csv`, опционально `tags.csv`), например `ml-25m`, работает с
`--dataset movielens`. Версии `ml-1m` и `ml-100k` имеют другой формат файлов и требуют конвертации.
Для очень больших наборов не включайте SVD и ограничьте число моделей: оценка идёт по всему каталогу.

### Универсальный загрузчик `--dataset amazon`
Принимает папку с файлами:
- `ratings.csv` - колонки `user,item,rating,timestamp` (`timestamp` необязателен; без него сплит случайный);
- `items.csv` (необязателен) - колонки `item,title,description,category` (категории через `|`).
  Без него контентная модель не имеет признаков.

Загрузчик считает данные явными, релевантными - оценки ≥ 4. Для другой шкалы или данных без оценок измените
`rel_threshold` и `explicit` в функции `load_amazon` (`recsys_lib/data.py`). Загрузчик `amazon` проверен только
по общей логике пайплайна, на реальных наборах не запускался.

### Добавление своего датасета
Реализуйте функцию загрузки, возвращающую объект `Dataset` (взаимодействия, метаданные, флаг явных оценок,
порог релевантности, флаг хронологического сплита), и добавьте её в словарь `LOADERS` в `recsys_lib/data.py`.

## 13. Типичные проблемы

| Симптом | Причина и решение |
|---|---|
| `ImportError: ... scikit-surprise` / `implicit` | библиотека не установлена: см. раздел 2 или уберите `svd`/`als`/`bpr` из `--model` |
| `scikit-surprise` не собирается | `pip install scikit-surprise --no-binary scikit-surprise`, либо отдельное окружение |
| `RuntimeWarning: OpenBLAS is configured to use N threads` | задайте `OPENBLAS_NUM_THREADS=1` (раздел 4); это предупреждение, а не ошибка |
| `FileNotFoundError: ratings.csv` | неверный `--path`; внутри папки должны лежать файлы датасета, а не вложенная папка |
| `SVD требует явных оценок - пропущен` | SVD не применяется к Last.fm; это штатное поведение |
| Нет MMR-строк в таблицах | MMR применяется только к `content`; добавьте её в `--model` и задайте `--mmr` |
| Результаты ALS/BPR слегка отличаются от README | случайная инициализация и многопоточность; используйте `OPENBLAS_NUM_THREADS=1` и фиксируйте `--seed` |
| Мало памяти на больших датасетах | оценка идёт по всему каталогу батчами по 256 пользователей; уменьшите набор или число моделей |

## 14. Ограничения

- **Гиперпараметры:** число факторов (50) и итераций взято по умолчанию; подбор на валидационной выборке не проводился.
- **Холодный старт:** не тестировался (после k-core фильтра в данных нет новых пользователей и объектов).
- **Сплит на Last.fm:** случайный, без времени; метрики могут быть завышены.
- **Значимость:** проверялась по пересечению доверительных интервалов, без парного теста или bootstrap. Критерий
  консервативен: вердикт «незначимо» не доказывает отсутствие различия. Для MMR значимость не проверялась.
- **Разнообразие:** считается в том же TF-IDF-пространстве, в котором работают контентная модель и MMR, поэтому смещено в их пользу.
- **Один прогон:** результаты получены для одного seed; разброс между запусками не оценивался.
- **Признаки контентной модели:** у MovieLens нет описаний фильмов, только жанры, теги и название.
- **Ручной разбор** (`cases.md`) выполняется на четырёх пользователях и носит иллюстративный характер.
- **Загрузчик `amazon`:** универсальный, на реальных наборах не проверялся.

## 15. Воспроизводимость

- `--seed 42` по умолчанию; фиксирует сплит Last.fm и инициализацию моделей.
- Версии, использованные для разработки: scikit-surprise 1.1.5, implicit 0.7.3, numpy 2.x.
- Все версии библиотек, размеры данных и время обучения каждого запуска записываются в `run_log.json`.
- Для побитовой воспроизводимости ALS/BPR задавайте `OPENBLAS_NUM_THREADS=1`.
